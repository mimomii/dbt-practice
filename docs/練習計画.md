# dbt練習計画

使用データ: `SNOWFLAKE_SAMPLE_DATA.TPCDS_SF10TCL`（小売業の取引データ）

---

## ステップ1: stagingモデルを作る

**目的**: ソーステーブルをそのまま軽くクリーニングする1:1モデルの書き方を覚える

**やること**:
- `models/staging/` フォルダを作成
- `sources.yml` でソーステーブルを定義
- 以下のテーブルをstagingモデルとして作成

| モデル名 | ソーステーブル | 内容 |
|---|---|---|
| `stg_customer` | `CUSTOMER` | 顧客マスタ |
| `stg_store_sales` | `STORE_SALES` | 店舗売上明細 |
| `stg_item` | `ITEM` | 商品マスタ |
| `stg_date_dim` | `DATE_DIM` | 日付ディメンション |

**学べること**: `source()` 関数、カラムのリネーム、型キャスト

---

## ステップ2: intermediateモデルを作る

**目的**: 複数テーブルのJOINと集計を練習する

**やること**:
- `models/intermediate/` フォルダを作成
- stagingモデルを組み合わせて中間テーブルを作成

| モデル名 | 内容 |
|---|---|
| `int_sales_with_customer` | 売上に顧客・商品情報をJOIN |
| `int_daily_sales` | 日別の売上集計 |

**学べること**: `ref()` 関数、Jinjaテンプレート、CTEの書き方

---

## ステップ3: martモデルを作る

**目的**: BI向けの最終テーブルを作り、マテリアライゼーションを使い分ける

**やること**:
- `models/marts/` フォルダを作成
- intermediateモデルをもとに集計テーブルを作成

| モデル名 | マテリアライゼーション | 内容 |
|---|---|---|
| `mart_monthly_sales` | `table` | 月別売上サマリー |
| `mart_customer_summary` | `table` | 顧客別購買サマリー |

**学べること**: `{{ config(materialized='table') }}`、`view` vs `table` の使い分け

---

## ステップ4: テストを書く

**目的**: データ品質テストの書き方を覚える

**やること**:
- `schema.yml` にビルトインテストを追加
  - `not_null`、`unique`、`accepted_values`、`relationships`
- `tests/` フォルダにカスタムSQLテストを追加

**例**:
```yaml
models:
  - name: stg_customer
    columns:
      - name: customer_sk
        tests:
          - not_null
          - unique
```

**学べること**: ビルトインテスト4種、カスタム単体テスト

---

## ステップ5: incrementalモデルを試す

**目的**: 大量データの差分更新パターンを覚える

**やること**:
- `store_sales` を使ったincrementalモデルを作成
- `is_incremental()` フィルタで差分取得を実装

```sql
{{ config(materialized='incremental', unique_key='ss_ticket_number') }}
select ...
{% if is_incremental() %}
  where ss_sold_date_sk > (select max(ss_sold_date_sk) from {{ this }})
{% endif %}
```

**学べること**: incrementalの仕組み、コスト削減の考え方

---

## ステップ6: ドキュメントを生成する

**目的**: `dbt docs` でドキュメントサイトを生成・確認する

**やること**:
- `schema.yml` に `description:` を追記
- `dbt docs generate && dbt docs serve` で確認
- リネージグラフ（DAG）を眺める

---

## コスト注意事項

- ウェアハウスは常に **X-Small** を使用
- `dbt run` 後は Snowflake コンソールでウェアハウスが停止していることを確認
- `dbt compile` で SQL を確認してから `dbt run` する習慣をつける
